# 트레이 상호작용 수정 계획

## 목표

Windows 설정 창의 `트레이로 숨기기` 버튼을 실제로 동작하게 만들고, 트레이 아이콘의 더블 클릭과 우클릭 메뉴로 설정 창을 다시 열거나 프로그램을 종료할 수 있게 한다.

## 확인된 원인

- 버튼 클릭이 만드는 `WM_COMMAND`는 부모 창 프로시저로 동기 전송된다.
- 현재 코드는 큐에서 꺼낸 메시지만 `read_ui_event`로 해석하므로, 부모 창 프로시저가 받은 `WM_COMMAND`가 앱 이벤트 처리기로 전달되지 않는다.
- 그 결과 `트레이로 숨기기`를 포함한 버튼/체크박스 명령이 앱 컨트롤러 경로에 도달하지 않는다.
- 트레이 더블 클릭 및 우클릭 메뉴 코드는 이미 존재하지만, 실제 숨김 경로와 함께 회귀 방지 검증을 보강해야 한다.

## 수정 범위

- `src/platform/windows/ui/window.rs`
  - 부모 창 프로시저가 `WM_COMMAND`를 앱 전용 메시지로 안전하게 전달하도록 수정한다.
  - 앱 전용 메시지를 기존의 타입화된 `UiEvent`로 변환한다.
- `src/platform/windows/ui/tray.rs`
  - 더블 클릭은 기존 설정 창을 표시하고 전경으로 가져온다.
  - 우클릭은 `설정 열기`, 현재 활성 단축키 요약, `종료` 메뉴를 표시한다.
  - 필요한 경우 Windows 권장 팝업 메뉴 포커스/종료 처리를 보강한다.
- `src/ui_model.rs`, `tests/ui_model.rs`
  - 명령 및 트레이 이벤트 변환의 회귀 테스트를 추가하거나 보강한다.
- `docs/HVC-WINDOWS.md`
  - 사용자가 보고한 v0.1.0 트레이 결함과 패치 후 실기기 재검증 항목을 기록한다.

## 수용 기준

1. `트레이로 숨기기` 클릭 시 설정 창만 숨고 프로세스와 트레이 아이콘은 유지된다.
2. 숨겨진 상태에서 트레이 아이콘을 더블 클릭하면 기존 설정 창이 다시 나타나고 전경으로 이동한다.
3. 트레이 아이콘을 우클릭하면 `설정 열기`, 활성 단축키 요약, `종료`가 표시된다.
4. `설정 열기`는 기존 설정 창을 표시하고, `종료`는 메시지 루프를 정상 종료한다.
5. 체크박스 즉시 반영, 창 닫기/ESC 숨김, 단일 인스턴스, 단축키 기능은 회귀하지 않는다.
6. 변경된 Rust 소스 파일은 각각 500줄 미만을 유지한다.

## 검증 계획

- 관련 단위 테스트를 먼저 실패시키고 수정 후 통과시킨다.
- `cargo fmt --check`
- `cargo test --all-targets`
- `cargo clippy --all-targets -- -D warnings`
- `cargo check --target x86_64-pc-windows-msvc --all-targets`
- `cargo clippy --target x86_64-pc-windows-msvc --all-targets -- -D warnings`
- `git diff --check` 및 Rust 파일 줄 수 확인
- macOS 개발 호스트에서는 실제 트레이 클릭 HVC가 불가능하므로, 패치 릴리스 전에 Windows 10/11 실기기에서 세 동작을 직접 확인한다.

## 제약과 위험

- 창을 숨겨도 핫키 등록과 트레이 수명은 유지해야 한다.
- 새 창을 만들지 않고 기존 창 핸들을 재사용해야 한다.
- Win32 메시지 전달 시 Rust 포인터를 저장하거나 넘기지 않고 정수/핸들 값만 사용한다.
- 이번 요청 범위에서는 GitHub 푸시와 공개 재배포를 수행하지 않는다. 구현·검증 후 `v0.1.1` 패치 릴리스 여부를 별도로 승인받는다.
